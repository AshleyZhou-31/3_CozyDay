Week of Sept 15, 2026 — Rishabh

- `planitem_list_manual` (HttpResponse FBV): `/planitems/manual/` manually
  loads and renders the PlanItem list template, then wraps it in HttpResponse.
- `planitem_list_render` (render shortcut FBV): `/planitems/render/` queries
  PlanItem records and passes them to the same template with render().
- `PlanItemListBaseView` (base View CBV): `/planitems/cbv-base/` implements
  get(), queries PlanItem records, and renders the shared template.
- `PlanItemListView` (generic ListView CBV): `/planitems/cbv-generic/` uses
  Django's model-backed ListView and the shared template.
- All four routes are named in planner/urls.py and show the same PlanItem
  data. Browser evidence: ../screenshots/section2/.
- Comparison: HttpResponse makes each rendering step explicit and is useful
  for learning or unusual response handling; render() is shorter for a
  standard template response. A base View gives control over request methods,
  while ListView removes boilerplate for a conventional model list.

Week of Sept 28, 2026 — Shivani (Assignment 3, Section 4 — Matplotlib category chart)

- Added /planitems/chart/category.png, which returns a bar chart of plan
  item counts per category, and /planitems/analytics/, which embeds it
  with a heading, caption, and alt text.
- Data comes from the ORM: Category.objects.annotate(item_count=
  Count("plan_items")). The chart is computed live on every request.
- Set matplotlib.use("Agg") before importing pyplot. The server has no
  display, and the default macOS GUI backend fails inside the server
  thread.
- Used BytesIO so the chart is rendered in RAM and never written to disk.
  The buffer is discarded after the response, so no chart files pile up
  in the repo or on the server.
- Called plt.close(fig) after saving. pyplot keeps a reference to every
  figure it creates, so without closing it each page load would leak a
  figure and memory would grow over time.
- Regenerating on every request is fine at this scale. With heavy traffic
  the image could be cached.
- Forced whole numbers on the y-axis (MaxNLocator(integer=True)) because
  plan items are counted in integers.
- Added an Analytics link to the shared nav in base.html using
  {% url 'planner:analytics' %}. This touches a shared file, so I'm
  flagging it for review.
- Browser evidence: ../screenshots/section4/ (direct PNG URL and the
  analytics page).

Note for team: matplotlib is a new dependency. After pulling this branch,
